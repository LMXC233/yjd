# 双构建模式：微服务为主形态，单体为演示交付形态

线上环境是 2C2G/3M 单机且不承载真实流量；开发与压测环境（8G WSL）承载完整分布式形态。我们决定同一代码库支持两种构建：**微服务模式**（每模块独立启动器 + OpenFeign 远程调用 + RocketMQ 事件 + Nacos 注册配置）用于开发与压测；**单体模式**（一个聚合启动器将全部业务模块装配进单进程，模块间调用切换为本地实现、事件切换为 Spring 进程内事件、不依赖 Nacos/RocketMQ）用于线上演示交付（内存预算：单体 JVM ~1.1G + MySQL ~0.5G + Redis ~0.1G + OS ≈ 1.9G，塞进 2G）。

实现约束：模块间调用必须经 api 接口层抽象（Feign 远程实现 / 本地实现按 Profile 装配）；领域事件必须经事件总线抽象（MQ 实现 / 进程内实现），保证两种模式跑同一套业务代码。被拒候选：线上原样部署微服务栈（2C2G 装不下约 5.5-6G）；线上只放静态落地页（丢失可演示性）。
